# Citations

## What users see
Every tool page renders `CitationBox.astro`: a format dropdown (APA 7, MLA 9, Chicago, Vancouver, BibTeX, RIS), the formatted citation, and a Copy button. The site-wide citation lives on `/about/#cite`. Formats are generated by `site/src/lib/citation.ts` from the manifest `citation` block; no tool-specific code is needed.

## What a tool must provide
- `tool.json` → `citation`: `authors[] {family, given, orcid?}`, `year`, `title`, `doi` (null until minted), `version` (defaults to tool version), `preferredFormat`, `alsoCite[]` for underlying methods/papers the user should also cite.
- `CITATION.cff` in the tool folder (GitHub renders a "Cite this repository" button from the root one; per-tool files make the folder self-describing when downloaded).

## DOIs (recommended once a tool is `stable`)
1. Enable the **Zenodo–GitHub integration** for the repo (one click at zenodo.org/account/settings/github).
2. Create a GitHub **release** tagged `tools/<slug>-v<version>` (or a site-wide release). Zenodo archives it and mints a DOI (plus a concept DOI for all versions).
3. Put the version DOI in `tool.json → citation.doi` and in `CITATION.cff`, bump nothing else, rebuild.
Per-tool DOIs are cleaner for citation counts; a site-wide concept DOI is simpler. Default: site-wide concept DOI in the root `CITATION.cff`, per-tool DOIs only for tools with a method worth citing on their own.

## Academic standard
Software citation follows the FORCE11 Software Citation Principles: creator, title, version, publisher/repository, year, persistent identifier (DOI or URL), access date for web tools. The APA 7 "[Computer software]" form is the default.
